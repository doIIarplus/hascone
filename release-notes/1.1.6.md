SHINE skill scanning, 1440p support, and more reliable stat recognition

- Added a fresh, padded-crop retry for unclear Character Info numbers, including Ignore Defense. Numeric readings at 90-97% confidence can now be accepted when a fresh, differently processed reading agrees. Conflicting readings are rejected, and character identity checks remain strict.
- Low-confidence errors now show two decimal places and the required confidence, instead of rounding a rejected reading up to "97%."
- Fixed Sia Astelle character creation being rejected as unsupported. Its equipment scoring now uses INT, LUK, and Magic Attack alongside the existing Scouter class data.

- Added 2560 x 1440 capture support for Default Ratio (Filter Applied), including windowed and fullscreen client capture. Panel detection now accounts for the stretched UI, and hover coordinates, previews, and saved equipment icons use the same corrected scale.
- Improved filtered equipment tooltip border detection and restored small HEXA Matrix digit edges without relaxing numeric verification. Required-level retries now tolerate the optional period in "Lv." while still checking every level and reduction number.

- Added a dedicated SHINE skill scanner for Sia Astelle and Erel Light. It reads the top and bottom of Skills → VI, handles truncated skill names and shared mastery levels, and processes captures in the background. Inactive skills are set to zero only after the pages prove the complete list was covered; conflicting levels or interrupted scans preserve previous readings.
- SHINE profiles now show SHINE Tree of Stars with its in-game icon and hide unavailable placeholder mastery cores. The Erda Link Stats skill level is never used as a HEXA Stat core count.

- Fixed Character Info tooltip detection getting stuck when the cursor overlaps the start of the Applied Value heading, including the Attack Power breakdown. The scanner can recognize the unobscured heading while retaining numeric verification.
- Guided character scans now skip the weapon attack step when equipment processing has already supplied it, including equipment readings that finish in the background after the guide opens. An already-visible weapon step no longer fails with "Unknown scan step."
- Added automatic retries for brief connection failures while fetching scan progress and other saved data. Scan-start and save requests are not automatically repeated, preventing duplicate actions when a response is lost.
